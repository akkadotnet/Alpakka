# Azure Pipelines Build Files
These `.yaml` files are used by Windows Azure DevOps Pipelines to help execute the following types of builds:

- Pull request validation on Linux (Mono / .NET Core)
- Pull request validation on Windows (.NET Framework / .NET Core)
- NuGet releases with automatic release notes posted to a Github Release repository.

**NOTE**: you will need to change some of the pipeline variables inside the `windows-release.yaml` for your specific project and you will also want to create variable groups with your signing and NuGet push information.

The required Windows driver-upgrade check runs the frozen .NET Framework consumer against the exact candidate archive with output binding redirects generated by MSBuild, including the old executable among its reference inputs. It preserves non-binding host settings and checks executable/runtime DLL hashes even on failure. The expected raw SDK binding failure must occur before and after the generated-policy success; the separate frozen old IDelivery implementation must still reject the incompatible AMQPNetLite2.5.5 interface. This verifies a normal NuGet upgrade with generated output configuration, not a DLL-only swap with byte-identical generated configuration or arbitrary custom binding policies. API, retained TFM, package and native integration gates remain required; the separate old/new wire-encoding comparison is local evidence.
